# 报告逻辑验证记录

日期：2026-10-23。范围：开发验证与合成记录，未调用模型、未使用个人真实数据，也没有用户效果或模型排名结论。

## 问题与改变

原实现会用实际选择B的结果给推荐A的概率计分；现仅对已结算、实际选择推荐选项的二元结果计分，其他记录给出排除原因和ID。采用率分母改为曾收到推荐的人工决策，并显式给出分子、分母。

合成CLI联通检查还发现：`resolve`不填可选`--notes`时，空字符串被当作必填文本而拒绝。现使可选空文本与省略字段一致，必填文本仍要求非空。

## 可重跑检查

在仓库根目录运行：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

结果：7项测试通过，覆盖替代选项成功时不计分、合格成功/失败记录、未知与部分结果、未结算、纯人工决策、非法概率、缺少人工选择，以及使用默认空备注的合成CLI完整流程。测试定义位于 `tests/test_report.py`，只写临时目录。

合成CLI流程经过 `create → baseline → recommend → decide(另一个选项) → resolve → report → verify`，验证5个事件的哈希链。它验证接口连接与报告行为，不是真实模型接入验收。

## 反证

用修改前的 `report.py` 对“推荐A、执行B、B成功”用例运行相同断言，原实现得到 `n=1`，正确预期为 `n=0`，断言失败。原始CLI检查也实际捕获了省略备注被拒绝的问题。因此测试覆盖了真实存在的回归，不能以这些测试推断整个协议或全部边界均已正确。

版本化目标事件、预测时点与期限、原始事实更正、库层状态机和真实模型链路尚未实现。`calibration`键保留以兼容旧JSON输出；Brier分数只是所选子集的概率损失。未选择方案的反事实结果仍未知；样本选择、个人时间依赖和分布漂移限制其解释。
